# Fix renamed host/remote repo URLs across the VitePress docs

## Context

The GitHub repositories for the host and remote starter templates were renamed:

| Old repo slug | New repo slug |
| --- | --- |
| `your-org/mono-host` (Vue host) | `your-org/mono-vue-host` |
| `your-org/mono-vue` (remote) | `your-org/mono-vue-remote` |
| — (new) | `your-org/mono-nuxt-host` |

The VitePress docs under `demo/vitepress/docs/repo/` still pointed at the old slugs, so the
"Starter repo" links and the `mono.config.ts` sync examples were 404s. This change fixes those
wrong URLs (and the repo-root folder labels in the tree diagrams that name the repo) so the docs
match reality.

**Decisions:**
1. **Repo slug ≠ app name.** Only the GitHub URLs and the repo-root clone-dir labels in tree
   diagrams change to the new slugs. The app `name:` values, `.apps/<name>/` paths, and the
   `@mono-host` / `@mono-vue` import aliases stay as-is — because `monoAlias()` derives every alias
   as `@` + the app's `name:` (`packages/utility/src/composables/mono-alias.ts:139-168`), so
   renaming them would break the aliases we keep. A one-line note clarifies that the GitHub repo is
   `mono-vue-host` / `mono-vue-remote` while the internal app name (and `@`-alias) stays
   `mono-host` / `mono-vue`.
2. **Nuxt host: left out entirely.** No mention of `mono-nuxt-host` anywhere.
3. **Scope = source `.md` only.** `demo/vitepress/docs/.vitepress/dist/` is gitignored and
   regenerated by `vitepress build`.
4. **The `github.com/your-org/libs#path:/packages/...` install URLs are correct and untouched.**

## Changes applied

### A. GitHub starter-repo URLs (`mono-host` → `mono-vue-host`, `mono-vue` → `mono-vue-remote`)
- `repo/template.md` — both `Starter repo:` lines (Host / Remote sections).
- `repo/sync.md` — the two "Mono Host" / "Mono Remote" link targets, the `url:` in the
  `mono.config.ts` example, and the four `…/tree/…` ref examples.

### B. Repo-root (clone-dir) folder labels in tree diagrams → new repo slug
- `repo/sync.md`, `repo/env.md`, `repo/template.md`: `mono-vue/` → `mono-vue-remote/`
  (the `.apps/mono-host/` lines inside those trees stay).
- `repo/config.md`: both `mono-remote/` tree roots → `mono-vue-remote/`.

### C. Kept unchanged (intentionally)
- All `@mono-host` / `@mono-vue` (+ `-root`) aliases and their `.apps/mono-host` / `.apps/mono-vue`
  resolution rows/trees (`template.md`, `odata-types.md`).
- All app `name:` values (`mono-remote` / `mono-host` / `mono-vue`) in `sync.md`, `config.md`,
  `data-fetching.md`.
- `env.md` app-name tokens: `.apps/mono-host/`, `mono env -a mono-host`, `MONO_APP_NAME` example,
  `from mono-vue / mono-host`.
- The `github.com/your-org/libs#path:/packages/...` install URLs.

### D. Added one clarifying note
- `repo/template.md`: a one-line "Repo name vs app name" note after the alias-resolution table.
