# Menu (recursive nav list) component + docs

## Context

Third and final of the Vuetify-style **layout primitives** the user requested:
`mono-nav` → `mono-sidebar` → `mono-menu`. With this shipped, the full app-shell
composition — sticky top bar + side drawer + recursive nav list — is feasible from a
single `items` array with theme-aware accents, layout-var coordination, and standalone
CSS demos that mirror the Lit element exactly.

`mono-menu` maps onto Vuetify's `<v-list>` + `<v-list-item>` + `<v-list-group>` trio,
collapsed into a single recursive component driven by an `items` array. Items can be
plain rows, collapsible groups, dividers, or subheaders — discriminated by an optional
`type` field. Single or multi-select, three densities, seven theme colors, two style
variants (`nav` for the dashboard pill, `plain` for context-menu fill), plus
`badge` / `badgeColor` per row and `slot="icon-${id}"` for SVG icons.

The sidebar's `with-menu` demo (Vue + CSS) was rewritten to consume `<mono-menu>` in the
sidebar's body slot, replacing the hand-rolled list and giving the app-shell composition
its first real end-to-end demo.

## Files added

### Lib

- `src/components/menu/index.ts` — re-exports.
- `src/components/menu/mono-menu.ts` — Lit element. `createRenderRoot()` returns the host
  (light DOM). Recursive `_renderList(items)` walks the tree and dispatches to four
  per-type renderers: `_renderItemRow` (button/anchor + optional `children` sub-list),
  `_renderGroup` (collapsible header + body list), `_renderDivider`, `_renderSubheader`.
  Group expand/collapse state is tracked in a local `Set<string>`; default-open ids are
  seeded once on connect from `collectDefaultOpenGroups(items)`. Slot capture
  (`connectedCallback` → `data-mono-slot="icon-${id}"`) mirrors `mono-tabs`'s pattern,
  so SVGs slotted as `<svg slot="icon-${id}">` substitute for the item's `icon` string.
- `src/components/menu/menu-types.ts` — `MenuDensity`, `MenuColor`, `MenuBadgeColor`,
  `MenuItem` (the recursive shape), `MenuCssClass`, the three event details
  (`mno-change`, `mno-click`, `mno-toggle-group`), `MenuProps`, `MenuEvents`.
- `src/components/menu/menu-utils.ts` — `isItem`, `isGroup`, `isDivider`,
  `isSubheader`, `findItem(items, id)`, `findActivePath(items, id)`,
  `collectDefaultOpenGroups(items)`, `generateMenuRootClasses({…})`,
  `validateMenuProps(props)`.
- `src/components/menu/menu.css` — variables on `.mono-menu` (light-DOM rule). Density
  blocks scale `--menu-pad-x/y`, `--menu-gap`, `--menu-font`, `--menu-icon-size`, and
  the per-level `--menu-indent`. Six themed color modifiers + `surface` redirect
  `--menu-accent`. The `nav` variant paints active rows with the dashboard gradient
  pill (matches `template/dashboardV2.html`'s `.nav-item.active`); the `plain` variant
  uses a soft `rgba(accent, 0.12)` fill and accent text — better for context menus.
  Nested lists indent by `--menu-indent` and gain a faint left guide rail. Group
  headers have a chevron that rotates 90° when `data-open="true"`. Divider is a 1 px
  hairline; subheader is a tiny uppercase label. Reduced-motion override.

## Patterns followed

- **Light DOM render**: `createRenderRoot() { return this }`. Variables on `.mono-menu`,
  not `:host`. Per the codified light-DOM rule.
- **Discriminated-union items**: `MenuItem.type` (`undefined | 'item' | 'group' |
  'divider' | 'subheader'`) mirrors Vuetify's `<v-list>` + slot conventions but as
  data, so the entire menu can be configured from a single JSON-serializable array.
- **Recursive rendering**: `_renderList` is the single point of recursion; both
  per-item `children` (auto-indent sub-list) and group `children` (collapsible
  sub-list) reuse it. Visual depth is conveyed via `--menu-indent` + a faint guide
  rail per nesting level.
- **Two visual variants**: `nav` (default, gradient pill — matches the dashboard
  template) and `plain` (subtle fill — for context menus / dropdowns). Driven entirely
  by CSS classes; same DOM.
- **Theme integration**: every accent reads `var(--theme-X)`. Active row gradient
  blends `var(--menu-accent)` with `color-mix(... 70%, white)`. Global theme switcher
  recolors the accent without touching the Lit element.
- **Vue array/object prop rule**: `items` is `attribute: false`. Demos bind
  `:items.prop="items"`. Multi-select `modelValue` (an array) also uses
  `:model-value.prop="selected"` to avoid string coercion.
- **Vue v-model rule**: `:model-value` + `@mno-change="x = $event.detail.modelValue"`.
- **Vue named-slot rule**: `<svg slot="icon-${id}">` (no `<template #...>`).
- **CSS-only demos shareable**: same `.mono-menu` class set works in Lit and
  hand-written HTML. Inline `<script>` toggles `.active` / `aria-selected` /
  `data-open` for stateful demos.
- **Sidebar integration**: `with-menu` demos in both Vue and CSS were rewritten to
  consume `<mono-menu>` in the sidebar's body slot. The full Vuetify-style app shell
  is now declarative end-to-end.

## Out of scope for this session

- **Per-item `prepend` / `append` / `title` / `subtitle` slot routing**: only
  `slot="icon-${id}"` is supported in v1. Adding more slots would need additional
  `data-mono-slot` targets per item — easy to layer later if real-world demand
  appears.
- **Keyboard navigation (arrow keys, Home/End)**: focus is delegated to the focused
  button's native key handling for now. Roving tab-index + arrow nav is a quality-of-
  life enhancement deferable to a follow-up session.
- **Item search / filtering**: the menu renders the array as-is. A future
  `mono-menu-search` slot or `searchTerm` prop could filter the rendered items.
- **Drag-and-drop reordering**: out of scope for a layout-primitive component.
- **Auto-collapse-other-groups**: a `mode="single-open"` could enforce only one
  expanded group at a time, mirroring Vuetify's `v-list[expand-icon][open-strategy]`.
  Skipped for v1 — can compose externally by listening to `mno-toggle-group` and
  calling `collapseGroup(otherId)`.
