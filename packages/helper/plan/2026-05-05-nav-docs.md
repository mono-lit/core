# Nav (top app bar) component + docs

## Context

First of the three Vuetify-style **layout primitives** the user requested: `mono-nav`,
`mono-sidebar`, `mono-menu`. The `template/dashboardV2.html` mockup hand-rolled a topbar
each time it was needed; this session ships a reusable `<mono-nav>` element wired to the
shared `--theme-*` palette so the global VitePress theme switcher recolors it.

Mapped from Vuetify's `<v-app-bar>` with three densities (compact / comfortable / default
= 48 / 56 / 64 px), three variants (flat / elevated / outlined), and seven colors (six
themed + `surface` for the default white-with-themed-border look). No events of its own —
all behavior is consumer-side via slotted buttons.

The nav also writes its resolved height to `--mono-nav-height` on
`document.documentElement`, so future layout work (sidebar + content padding) can read
the value without a Lit context provider. A `.mono-layout-content` helper class is
shipped in `nav.css` to use the var.

## Files added

### Lib

- `src/components/nav/index.ts` — re-exports.
- `src/components/nav/mono-nav.ts` — Lit element. `createRenderRoot()` returns the host
  itself (light DOM). On `connectedCallback`, captures every direct child into one of
  four buckets keyed by the `slot` attribute (`start` / `end` / `extension` / `default`),
  removes them from the host, and re-inserts them into matching `[data-mono-slot]`
  targets in `updated()`. Whitespace-only text nodes and comment nodes are skipped during
  capture. Writes `--mono-nav-height` to `:root` on connect / density change; clears it
  on disconnect.
- `src/components/nav/nav-types.ts` — `NavDensity`, `NavColor`, `NavVariant`,
  `NavCssClass`, `NavProps`, `NavEvents` (intentionally empty — nav emits nothing).
- `src/components/nav/nav-utils.ts` — `getNavHeight(density)`,
  `generateNavRootClasses({…})`, `validateNavProps()`.
- `src/components/nav/nav.css` — variables on `.mono-nav` (NOT `:host`; light-DOM rule).
  `mono-nav { display: block }`. Three density blocks scale `--nav-height`,
  `--nav-pad-x`, `--nav-gap`, and `--nav-extension-height`. Six themed color modifiers
  redirect `--nav-accent` and paint the bar (`--nav-bg: var(--nav-accent)`, white text).
  `surface` keeps the white background with themed border + backdrop-blur. Variants
  (`flat` / `elevated` / `outlined`) toggle shadow / border. `.mono-nav.sticky` applies
  `position: sticky; top: 0; z-index: 30`. Inner row is flex with three slot containers
  (`mono-nav-start`, `mono-nav-center` = default slot, `mono-nav-end`). Optional
  extension row beneath the main row is hidden unless `.has-extension` is on the root.
  Auto-density rules under 640px viewport. Reduced-motion override.
  Bonus: ships a `.mono-layout-content` helper that pads itself by
  `var(--mono-nav-height, 0)` + `var(--mono-sidebar-{left,right}-width, 0)` so consumers
  can wrap their main content without prop drilling.

## Demo set (9)

## Patterns followed

- **Light DOM render**: `createRenderRoot() { return this }`. CSS variables hang off
  `.mono-nav`, not `:host`. Per the codified light-DOM rule.
- **Slot-routing pattern**: capture direct children once in `connectedCallback`; place
  into `data-mono-slot` targets on `updated()`. Default-slot (unattributed children) goes
  to the center container. Mirrors `mono-tabs` / `mono-accordion`.
- **Theme integration**: every accent reads `var(--theme-X)`. Six themed colors paint
  `--nav-bg` directly with white text. `surface` keeps the white-with-themed-border look
  with `backdrop-filter: blur(12px)` (matches the template's `.topbar` aesthetic). Global
  theme switcher recolors the bar accent + extension underline + focus rings.
- **No events, by design**: like Vuetify's `v-app-bar`, nav is layout. Slotted buttons
  carry their own handlers. Keeps the surface area small and predictable.
- **Layout-var coordination**: `--mono-nav-height` written on `document.documentElement`
  on connect (and on density change); cleared on disconnect. Sidebar will write its own
  width var the same way next session, so consumers can use a single
  `.mono-layout-content` wrapper to auto-pad.
- **Vue object-prop rule**: `customized` demo uses `:css-class.prop="{ inner, start,
  end }"`.
- **CSS-only demos shareable**: same `.mono-nav` class set works whether the consumer
  uses Lit or hand-written HTML.

## Verification

1. From `demo/vitepress/`, `pnpm dev`, open `/nav`.
2. All 9 demos render. Vue / CSS tabs look identical.
3. **basic**: bar sticks to top of the preview while scrolling.
4. **density**: 48 / 56 / 64 px heights stack vertically; spacing scales.
5. **colors**: `surface` + 6 themed accents; non-surface colors paint the entire bar.
6. **variants**: `flat` (no shadow), `elevated` (shadow), `outlined` (bottom border).
7. **with-extension**: second row appears beneath the main row; clicking tabs in the
   extension updates the active label below.
8. **non-sticky**: bar scrolls with the page.
9. **with-actions**: full dashboard top bar — brand, search input (centered), three
   action buttons + avatar on the right. Mirrors `dashboardV2.html` density.
10. **layout-var**: opens with a live readout of `--mono-nav-height` from `:root`. Value
    updates if a different density is selected on another `<mono-nav>` instance on the
    page.
11. **customized**: `:css-class.prop="{ inner, start, end }"` overrides apply per-section
    in Vue; matching utility classes apply in CSS.
12. **Theme switcher**: cycle the global theme — bar accents recolor with the rest of
    the page.
13. `pnpm build` — `dist/nav.js`, `dist/nav.d.ts` emitted; `dist/index.css` includes nav
    rules; type check passes.
